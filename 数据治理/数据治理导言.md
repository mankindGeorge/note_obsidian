# 数据治理（Data Governance）

> **定位来源**：[[数据资产管理]] > [[数据治理导言]]

---

### 一、 核心定义与治理对象

- **治理对象**：数据（指任何以电子或者其他方式对信息的记录，包括数据库表、文档、图片、日志、音视频等）。
- **核心定义**：围绕“谁对什么数据、按照什么规则、通过什么机制负责”，保障数据可用、可信、安全、可追溯并持续产生价值的一套制度、流程和技术安排。
- **核心关注维度**：
  - [x] **权责与规则（谁负责？什么规则？）**：明确组织架构分工、资产责任主体，以及统一的数据标准与合规策略。
  - [x] **机制与成效（如何执行？什么效果？）**：依托常态化运营流程与技术工具落实管控，最终实现资产价值释放与风险可控。

---

### 二、 治理目标与本质辨析

- **支撑作用**：为全组织跨部门提供统一的数据标准制定、主数据管理（MDM）、元数据血缘分析及权限与安全管控等体系化机制。
- **终极意图**：从战略与组织全局出发，打破数据孤岛，消除合规隐患，保障数据资产的长期可用、可信与安全，持续释放数据资产整体价值。

#### 概念辨析：数据清洗 vs 数据治理

| 比较维度 | 数据清洗 (Data Cleaning) | 数据治理 (Data Governance) |
| :--- | :--- | :--- |
| **本质定位** | 战术性、技术性执行步骤 | 战略性、体系化管理框架 |
| **作用范围** | 特定数据集、特定数据管道 (Pipeline) | 全组织、跨部门的所有数据资产 |
| **核心目标** | 消除脏数据，提升单表或特征数据的准确性与可用性 | 统一标准、明确权责、保障合规、释放整体资产价值 |
| **实施主体** | 数据工程师、数据分析师、算法工程师 | 数据治理委员会、数据资产管理员、业务与技术跨部门团队 |
| **执行周期** | 伴随 ETL 流水线或模型训练的阶段性操作 | 长期运营的制度、流程、规范与组织架构 |
| **常见手段** | 填补缺失值、去除重复项、异常值处理、数据类型转换 | 制定数据标准、主数据管理 (MDM)、元数据血缘分析、权限与安全管控 |
